🌍 Ключові моменти перед початком

🌐 1. Глобальний домен

Авторизуйтесь виключно на глобальному сайті www.aliexpress.com.

  • Уникайте регіональних піддоменів (.pl, .ru, .us).
  • Перед зняттям куків відкрийте розділ Монети на ПК, щоб згенерувати токени _m_h5_tk.

💵 2. Курс та валюта

У системі AliExpress монети уніфіковані для всіх країн:

  • 100 монет = $1.00 USD (1 монета = $0.01).
  • Щоденний звіт у Telegram автоматично показує баланс у монетах, доларах США та еквівалент у гривні (₴).

⏰ 3. Розклад запусків

Скрипт працює за всесвітнім часом (UTC):

  • Основний: 09:09 UTC (11:09 / 12:09 за Києвом)
  • Резервний: 14:09 UTC (16:09 / 17:09 за Києвом)
  • Затримка GitHub Cron на 5–20 хв у години пік є нормою.

🛡️ 4. Захист Alibaba WAF

Сервери GitHub працюють із дата-центрів США та ЄС.

  • Якщо система безпеки покаже капчу (RG_SEC), відкрийте додаток AliExpress на смартфоні або сайт у браузері та зберіть монети вручну один раз — блокування зніметься.

🔒 Клонування цього репозиторію у власний ПРИВАТНИЙ

🛡️ Чому потрібно саме приватне клонування, а не звичайний Fork?
GitHub не дозволяє зробити стандартний Fork публічного репозиторію приватним. А в приватному репозиторії (Private) сторонні користувачі не зможуть побачити ваші логи запусків, баланс монет чи назви ваших акаунтів. Оберіть будь-який зручний спосіб нижче:

Офіційний інструмент GitHub, який автоматично клонує цей репозиторій у ваш власний Private репозиторій прямо в браузері:

  1. Увійдіть у свій акаунт на GitHub.com.
  2. Натисніть іконку «+» у правому верхньому куті ➔ виберіть Import repository.
  3. У перше поле Your old repository’s clone URL вставте посилання на цей вихідний репозиторій.
  4. У поле Repository name введіть назву для вашої копії, наприклад: ali-farmer 📋.
  5. У блоці конфіденційності обов'язково виберіть 🔒 Private.
  6. Натисніть зелену кнопку Begin import — за 15–30 секунд повна приватна копія проекту буде готова!

Якщо ви звикли працювати з Git через консоль на своєму комп'ютері:

  1. Створіть порожній приватний репозиторій на GitHub: натисніть «+» ➔ New repository, вкажіть назву ali-farmer 📋, оберіть тип 🔒 Private і натисніть Create repository (галочку «Add a README file» ставити не потрібно).
  2. Клонуйте вихідний репозиторій собі на ПК та перейдіть у його папку: 
    git clone https://github.com/АВТОР/ali-farmer.git
cd ali-farmer
  3. Змініть адресу віддаленого репозиторію (origin) на свій щойно створений приватний репозиторій і відправте код: 
    git remote set-url origin https://github.com/ВАШ_ЛОГІН/ali-farmer.git
git branch -M main
git push -u origin main
  1. Якщо у репозиторії активна зелена кнопка «Use this template» (угорі праворуч): натисніть її ➔ Create a new repository ➔ введіть назву ali-farmer, оберіть 🔒 Private та натисніть Create repository. Це миттєво клонує весь проект у приватний репозиторій в один клік!
  2. Якщо ви робите звичайний Fork: після створення форку обов'язково відкрийте вкладку Actions у своєму репозиторії та натисніть зелену кнопку «I understand my workflows, go ahead and enable them» (інакше розклад у форках вимкнений за замовчуванням).

🤖 Створення Telegram-бота для щоденних звітів

  1. Відкрийте Telegram і перейдіть до офіційного бота @BotFather.
  2. Натисніть Start та надішліть команду створення нового бота: /newbot 📋.
  3. Введіть довільне ім'я бота (наприклад: AliExpress Coin Farmer).
  4. Введіть унікальний юзернейм, який обов'язково закінчується на bot (наприклад: max_ali_coins_2026_bot).
  5. Скопіюйте виданий HTTP API токен вигляду 7123456789:AAFlm3kX... — це ваш майбутній секрет TELEGRAM_BOT_TOKEN 📋.
  6. Відкрийте бота @userinfobot або @getmyid_bot, натисніть /start і скопіюйте ваш числовий ID (наприклад, 987654321) — це ваш TELEGRAM_CHAT_ID 📋.
❗ ОБОВ'ЯЗКОВИЙ ФІНАЛЬНИЙ ШТРИХ У TELEGRAM:
Перейдіть за посиланням на вашого щойно створеного бота у Telegram і натисніть кнопку START (/start). Якщо не активувати діалог першим повідомленням, Telegram заблокує доставку звітів із помилкою 400 Bad Request: chat not found!

🍪 Отримання авторизаційних Cookies із браузера

🔥 Профі-лайфхак для максимальної живучості сесії (Режим Інкогніто):
Відкрийте нове вікно браузера в режимі Інкогніто (Private Window), увійдіть на aliexpress.com, скопіюйте куки за інструкцією нижче і просто закрийте вікно Інкогніто (НЕ натискаючи «Вийти / Sign Out»). Так сесія для GitHub-скрипта буде ізольованою і не злітатиме під час вашого звичайного серфінгу!
  1. Встановіть розширення Cookie-Editor для вашого браузера (Chrome, Edge, Brave, Firefox).
  2. Перейдіть на сторінку монет AliExpress та переконайтесь, що ви авторизовані.
  3. Натисніть на іконку Cookie-Editor на верхній панелі розширень.
  4. Натисніть кнопку Export (внизу праворуч) ➔ виберіть Export as Header String.
  5. Готово! Повний текстовий рядок сесії вже у вашому буфері обміну.
  1. Відкрийте сторінку монет AliExpress та увійдіть в акаунт.
  2. Натисніть клавішу F12 (або Ctrl + Shift + I) і відкрийте вкладку Network (Мережа).
  3. Оновіть сторінку клавішею F5 і клацніть на найперший запит у списку (index.html або www.aliexpress.com).
  4. Праворуч у вкладці Headers прокрутіть до розділу Request Headers та знайдіть поле Cookie.
  5. Скопіюйте весь довгий вміст поля Cookie (без самого слова Cookie:).

🧪 Локальний перевіряльник рядка Cookie (100% офлайн у вашому браузері)

Вставте сюди скопійований рядок перед додаванням у GitHub, щоб перевірити, чи це правильний формат Header String (а не JSON) і чи присутні ключові токени авторизації:

⚠️ УВАГА: Не натискайте «Вийти» (Log Out)
Натискання кнопки виходу на сайті миттєво анулює скопійовану сесію на серверах AliExpress. Просто закрийте вкладку.

🔑 Додавання секретів у GitHub Actions

  1. У вашому клонованому приватному репозиторії на GitHub перейдіть на вкладку ⚙️ Settings (Налаштування).
  2. У лівому боковому меню розгорніть Secrets and variables ➔ виберіть Actions.
  3. Натискайте зелену кнопку New repository secret і по черзі створіть 3 обов'язкові секрети з таблиці нижче:
Назва секрету (клікніть для копіювання) Значення Статус
ALI_COOKIES 📋 Скопійований рядок Cookie з Кроку 3 (формат Header String) Обов'язково
TELEGRAM_BOT_TOKEN 📋 Токен бота від @BotFather із Кроку 2 Обов'язково
TELEGRAM_CHAT_ID 📋 Ваш числовий ID у Telegram із Кроку 2 Обов'язково
ALI_COOKIES_1 📋 ALI_COOKIES_2 📋 Додаткові сесії, якщо потрібно фармити 2 або більше акаунтів одночасно Опціонально

▶️ Перший тестовий запуск та перевірка звіту

  1. Перейдіть на вкладку ▶️ Actions у верхньому меню вашого репозиторію.
  2. У лівій панелі виберіть робочий процес AliExpress Daily Farm.
  3. Праворуч натисніть кнопку Run workflow ➔ у спадному вікні натисніть зелену кнопку Run workflow.
  4. Зачекайте 1–2 хвилини, поки статус зміниться на зелену галочку ✅, і перевірте повідомлення у вашому Telegram-боті!

🛠️ Діагностика помилок та Часті запитання (FAQ)

1. Скільки живуть Cookies і що робити при помилці SESSION_EXPIRED?

Зазвичай сесія живе від кількох тижнів до кількох місяців (особливо якщо вона була створена через вікно Інкогніто). Якщо у звіт прийде статус SESSION_EXPIRED, просто повторіть Крок 3 і оновіть секрет ALI_COOKIES у налаштуваннях GitHub.

2. Що означає помилка капчі (CAPTCHA / RG_SEC) у звіті?

Захисний фаєрвол Alibaba WAF тимчасово попросив підтвердження для IP-адреси дата-центру GitHub. Щоб зняти підозру:

  • Відкрийте мобільний додаток AliExpress на телефоні або сайт у браузері;
  • Перейдіть у розділ «Монети» і зробіть чекін вручну (посуньте слайдер капчі, якщо з'явиться);
  • При наступному плановому запуску скрипт продовжить роботу у штатному режимі.
3. Workflow на GitHub виконався успішно, але в Telegram нічого не прийшло

Перевірте 3 найчастіші причини:

  • Ви забули натиснути кнопку START (/start) у діалозі з вашим створеним ботом;
  • У секреті TELEGRAM_BOT_TOKEN або TELEGRAM_CHAT_ID є зайвий пробіл на початку чи в кінці;
  • Переплутані місцями токен бота та ID чату.
4. Чому через 60 днів автоматичний запуск на GitHub може зупинитися?

За правилами GitHub Actions, якщо в репозиторії протягом 60 днів немає жодної активності (комітів), розклад cron автоматично ставиться на паузу. GitHub надішле попередження на пошту — достатньо зайти у вкладку Actions і натиснути кнопку Enable workflow (або оновити будь-який файл).

5. Як підтягнути оновлення з авторського репозиторію у свій приватний клон?

Якщо ви клонували репозиторій через Git, додайте авторський репозиторій як upstream і підтягуйте зміни командою: git pull upstream main && git push origin main.
